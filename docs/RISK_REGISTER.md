# AeroSense AI V2 — Risk Register

> Phase 19 deliverable. Last updated: 2026-11-17.

## R-01 · Synthetic Training Data
| Field | Value |
|-------|-------|
| **Category** | Data Integrity |
| **Likelihood** | Realised |
| **Severity** | High |
| **Status** | Accepted / Disclosed |
| **Description** | Delhi, Mumbai, Vijayawada canonical datasets were generated by `np.random.RandomState` in `harmonizer.py`. No real CPCB downloads exist in the active repository. The synthetic generator uses physically plausible ranges but produces near-zero autocorrelation, which explains the negative R² values for the Persistence baseline. |
| **Mitigation** | Full disclosure in `docs/AUDIT_REPORT.md`. Checkpoint `stcnn_gru_delhi.pt` is marked as "trained on synthetic data". Future work: replace with real CPCB CAAQMS API exports. |

## R-02 · Google Drive Mount Failure in Colab
| Field | Value |
|-------|-------|
| **Category** | Infrastructure |
| **Likelihood** | High (credential propagation issue with multiple Google accounts) |
| **Severity** | Medium |
| **Status** | Mitigated |
| **Description** | `MessageError: credential propagation was unsuccessful` when mounting Drive in Colab if more than one Google account is logged into the browser. |
| **Mitigation** | Master notebook redesigned to use Colab Files panel upload (`files.upload()`) instead of Drive. `AeroSense_Colab_Bundle.zip` bundles all needed data into a single uploadable archive. |

## R-03 · Beijing Data Leakage into Active Paths
| Field | Value |

| **Category** | Data Governance |

| **Severity** | High |
| **Status** | Mitigated |

## R-04 · Class Name Mismatch in ST-CNN-GRU Checkpoint
| Field | Value |
|-------|-------|
| **Category** | Software Engineering |
| **Likelihood** | Realised |
| **Severity** | Medium |
| **Status** | Fixed |
| **Description** | `stcnn_gru_delhi.pt` was saved with class `STCNNGRUNetwork` but Colab notebook used `STCNN_GRU`, causing `ImportError`. |
| **Mitigation** | Checkpoint config documented: `input_size=57, cnn_channels=64, gru_hidden=128, gru_layers=2, seq_len=24`. Master notebook loads via `ckpt['network_state']` with correct class. |

## R-05 · GPU Memory Limits in Colab Free Tier
| Field | Value |
|-------|-------|
| **Category** | Compute |
| **Likelihood** | Medium |
| **Severity** | Medium |
| **Status** | Accepted |
| **Description** | STCNN-GRU with 12-station spatial attention and batch_size=32 may OOM on Colab T4 (15 GB VRAM) if sequence buffers are large. |
| **Mitigation** | Batch size reduced to 16 for spatial models. `pin_memory=False`. Gradient checkpointing enabled for GRU layers in notebook Cell 7. |

## R-06 · Vijayawada 2-Station Sparse Topology
| Field | Value |
|-------|-------|
| **Category** | Modelling |
| **Likelihood** | Realised |
| **Severity** | Medium |
| **Status** | Accepted |
| **Description** | Vijayawada APPCB data covers only 2 monitoring stations. The ST-CNN-GRU spatial attention graph requires ≥3 nodes for meaningful message-passing. |
| **Mitigation** | Transfer model uses adapter head strategy with frozen backbone. Minimum viable graph constructed with 2 real + 1 virtual centroid node. Status kept at `available` pending real checkpoint. |

## R-07 · Negative R² in Persistence Baseline
| Field | Value |
|-------|-------|
| **Category** | Metrics Integrity |
| **Likelihood** | Realised |
| **Severity** | Low |
| **Status** | Accepted |
| **Description** | Persistence baseline yields R² ≈ -4.4 for Delhi on synthetic data, since the synthetic generator decorrelates observations across timesteps. |
| **Mitigation** | Negative R² preserved as-is in all reporting per integrity rule. Explicitly noted in `evaluation_service.py` docstring and final report. |
